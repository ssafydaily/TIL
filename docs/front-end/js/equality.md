# 동등 (euality)

## `==` 와 `===` 연산자의 차이점


- `loose equality (==)`

  - 값만 비교하며, 비교 전에 두 값의 타입이 다르면 자동으로 타입을 맞춰서 비교(타입 강제 변환, type coercion)를 수행
  - 즉, 숫자와 문자열 등 서로 다른 타입이어도 내부적으로 타입을 맞춘 뒤 비교합니다.

- `strict equality` `===`

  - 값뿐만 아니라 타입까지 모두 같아야 true를 반환
  - 타입 변환을 하지 않음


## `==` 연산자의 형 변환 규칙 (우선순위)

규칙은 위에서 아래로 적용되며, 한 규칙이 적용되면 비교가 다시 시작됩니다.

### 1\. `null`과 `undefined`의 특별 규칙

가장 먼저 처리되는 예외입니다.

  * `null`과 `undefined`는 서로를 비교할 때만 `true`입니다.
    ```javascript
    null == undefined; // true
    undefined == null; // true
    ```
  * `null`이나 `undefined`를 다른 어떤 값과 비교해도 `false`입니다. (다른 규칙이 적용되기 전에 차단됩니다.)
    ```javascript
    null == 0;      // false
    undefined == 0; // false
    null == false;  // false
    ```

### 2\. 숫자 (Number) vs 문자열 (String)

한쪽이 숫자이고 다른 쪽이 문자열이면, **문자열을 숫자로 변환**하여 비교합니다.

```javascript
// 문자열 "10"이 숫자 10으로 변환됨
10 == "10"; // (10 == Number("10")) -> (10 == 10) -> true

// 문자열 "hello"가 NaN으로 변환됨
1 == "hello"; // (1 == Number("hello")) -> (1 == NaN) -> false
```

### 3\. 불리언 (Boolean) vs 다른 타입

한쪽이 불리언(`true`, `false`)이면, **불리언을 숫자로 변환**하여 비교를 다시 시작합니다.

  * `true` → `1`
  * `false` → `0`

<!-- end list -->

```javascript
// 1. 불리언이 숫자로 변환됨
true == 1; // (Number(true) == 1) -> (1 == 1) -> true
false == 0; // (Number(false) == 0) -> (0 == 0) -> true

// 2. 복합적인 경우: 불리언 -> 숫자 변환 후, 다시 문자열 -> 숫자 변환
true == "1";
// 1단계: (Number(true) == "1") -> (1 == "1")
// 2단계: (1 == Number("1")) -> (1 == 1) -> true
```

### 4\. 객체 (Object) vs 원시 타입 (Primitive)

한쪽이 객체(배열, 함수 포함)이고 다른 쪽이 원시 타입(Number, String, Boolean, Symbol)이면, **객체를 원시 타입으로 변환**하여 비교를 다시 시작합니다.

  * 객체는 내부적으로 `ToPrimitive` 동작을 통해 변환됩니다.
  * 대부분의 객체(배열 포함)는 `valueOf()`를 먼저 시도하고, 안 되면 `toString()`을 시도합니다.
  * `Date` 객체는 `toString()`을 먼저 시도합니다.

<!-- end list -->

```javascript
// 1. 배열(객체) vs 숫자
[10] == 10;
// 1단계: ([10].toString() == 10) -> ("10" == 10)
// 2단계: (Number("10") == 10) -> (10 == 10) -> true

// 2. 빈 배열(객체) vs 숫자
[] == 0;
// 1단계: ([].toString() == 0) -> ("" == 0)
// 2단계: (Number("") == 0) -> (0 == 0) -> true
```

## 🤯 주의해야 하는 경우

|  표현식     |  결과       |
|------------|------------|
| `0 == "0"` | **true**   |
| `0 == []`  | **true**   |
| `"0" == []`| **false**  |

### `0 == '0'`
- 여기서 0은 number, '0'은 string
- 문자열 '0'이 숫자 0으로 변환
- `0 == 0` 으로 **true** 가 반환

### `0 == []`
- 0은 number, []는 **object(배열)**
- `==` 연산 시, 객체([])는 **원시값(primitive)**으로 변환
- 배열의 `toString()`이 호출되고, 빈 배열은 **빈 문자열 ''**을 반환
- 다시 `0 == ''` 연산이 실행
- `''(빈 문자열)`이 숫자 0으로 변환되어 `0 == 0`이 되고, **true**가 반환

### `'0' == []`

- '0'은 string, []는 **object(배열)**
- `[]`는 객체이므로 원시값으로 변환되어 **빈 문자열 ''** 로 변환
- `'0' == ''` 은 **false**를 반환


JavaScript의 `==` (동등 연산자)는 피연산자의 타입이 다를 경우, **숫자(Number) 타입으로 변환하여 비교**하려는 경향이 강합니다.

이 변환 규칙은 "추상 동등 비교 알고리즘"이라는 ECMAScript 사양에 정의되어 있으며, 그 우선순위는 다음과 같습니다.


### 추가 예시

이 규칙들이 중첩되면 매우 직관에 어긋나는 결과가 나옵니다.

```javascript
// 예시 1:
[] == false;
// 1단계 (규칙 3): ( [] == Number(false) ) -> ( [] == 0 )
// 2단계 (규칙 4): ( [].toString() == 0 ) -> ( "" == 0 )
// 3단계 (규칙 2): ( Number("") == 0 ) -> ( 0 == 0 )
// 결과: true

// 예시 2:
"0" == false;
// 1단계 (규칙 3): ( "0" == Number(false) ) -> ( "0" == 0 )
// 2단계 (규칙 2): ( Number("0") == 0 ) -> ( 0 == 0 )
// 결과: true

// 예시 3:
" \t\r\n" == 0;
// 1단계 (규칙 2): ( Number(" \t\r\n") == 0 ) -> ( 0 == 0 )
// (공백 문자열은 숫자로 변환 시 0이 됩니다)
// 결과: true
```

## 결론 및 권장 사항

`==` 연산자의 형 변환 규칙은 복잡하고 예측하기 어렵습니다.

**따라서 JavaScript에서는 타입과 값이 모두 같은지 확인하는 `===` (일치 연산자)를 사용하는 것이 강력히 권장됩니다.**

```javascript
10 === "10"; // false (타입이 다름)
true === 1;  // false (타입이 다름)
[] === false; // false (타입이 다름)
null === undefined; // false (타입이 다름)
```
